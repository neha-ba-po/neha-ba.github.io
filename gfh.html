The challenge

Business rules had to survive the system boundary.

German energy pricing and regulatory logic had to be represented consistently across market data, CPQ decisions and downstream Billing. The challenge was making decision logic explicit enough for engineering, QA and business stakeholders to validate.

My contribution
  • Translated regulatory and business needs into epics, stories and acceptance criteria.
  • Designed CPQ-side integration and decision flows across PACS, CPQ and Billing.
  • Defined mapped-price, fallback and controlled-failure behavior.
  • Validated API behavior with Postman / Swagger and data with SQL.
  • Supported smoke, acceptance, E2E, UAT and release readiness.
Interactive logic map

Three outcomes from one decision point.

The simplified diagram mirrors the portfolio-level decision logic without exposing confidential implementation detail.

Path A

Mapped

PACS returns the relevant market-location mapping. CPQ applies the required article IDs/prices and statutory enrichment before the Billing handoff.

Path B

Fallback

If mapping is unavailable and product fallback is enabled, CPQ can use PACS PRICAT / price-sheet data as the designed fallback source.

Path C

Controlled failure

If fallback is not enabled, CPQ returns designed error codes so Billing can surface the appropriate user-facing message.

Evidence

What I validated.

  • API requests / responses and edge conditions.
  • SQL data values and root causes.
  • Acceptance criteria across happy and exception paths.
  • Grafana / Kibana logs for production issue investigation.
  • UAT and release readiness across integrated behavior.
Scope boundaryBilling's own calculation formula is outside the CPQ-side feature scope. My work focused on the upstream decision, enrichment, filtering, fallback and validated handoff.
